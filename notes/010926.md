# Java and JavaFX Drawing Exercises
*Tuesday, 1 September 2026*

## Topics Discussed

- Drawing a triangle from three equations entered as text
- Drawing circles on a JavaFX canvas with a right-click
- Connecting circles with arrows
- Representing a binary tree graphically

## Triangle from Three Equations

The first exercise was to create a JavaFX program in which the user enters three equations as text. Each equation represents one side of a triangle. The application must read the text, interpret the equations, and draw the three corresponding line segments on a canvas.

The important geometric step is finding the intersections of the three lines. If two lines are written in the form `y = m*x + c`, their intersection can be calculated by equating their right-hand sides:

`m1*x + c1 = m2*x + c2`

Therefore:

`x = (c2 - c1) / (m1 - m2)`

After calculating `x`, it can be substituted into either equation to obtain `y`. Repeating this for each pair of equations produces the three vertices. The program can then use JavaFX `Line` objects or a `Polygon` to draw the triangle. The equations must be validated because parallel, coincident, or incorrectly formatted lines cannot produce a unique triangle.

This exercise connects text input, parsing, algebra, coordinate geometry, and rendering. It also shows why the program should separate the input and calculation stages from the drawing stage. The calculated coordinates should be represented using a suitable numeric type, and the screen coordinate system may require transforming the mathematical y-axis because JavaFX coordinates increase downwards.

## Circles and Arrows on a Canvas

The second exercise was to draw a circle at the location of every right-click on a JavaFX `Canvas`. A mouse event handler can check whether the button is `MouseButton.SECONDARY`, then use the event's x and y coordinates as the centre of a new circle. The circle can be drawn with `GraphicsContext.fillOval` or `strokeOval`.

The circle centres need to be stored in a collection rather than only drawn once. Storing the points makes it possible to redraw the complete scene and to connect the circles with arrows. Each new circle can be connected to the previous circle, or the program can use a separate interaction mode for selecting the start and end circles of an arrow.

An arrow is more than a line. The shaft can be drawn between two centres, and a pair of short lines can form the arrowhead at the destination. The arrowhead direction is calculated using the angle from the first point to the second point. The line should normally stop at the circumference of the destination circle instead of passing through its centre. This requires shortening the line by the circle radius along the direction vector.

The exercise demonstrates event-driven programming, coordinate storage, redraw logic, and basic vector geometry. It also raises practical questions about selecting an existing circle, avoiding duplicate points, and deciding what should happen when the user clicks near an existing node.

## Binary Tree Drawing

The third exercise was to draw a binary tree. A binary tree consists of nodes, and each node can have at most one left child and one right child. A useful model is a `TreeNode` class containing a value and references to its left and right children.

The visual layout can be calculated recursively. The root is placed near the top centre of the drawing area. Each level below it is given a larger y-coordinate, while the x-coordinate is shifted left for a left child and right for a right child. Before drawing a node, the program should draw the edge from its parent to the node. It can then draw a circle and a text label for the node value.

A more general layout uses the available horizontal region: the left subtree receives the left half of the region and the right subtree receives the right half. This reduces overlap for trees with several levels. The tree should be drawn from the data structure rather than by hard-coding individual circles and lines, because the same renderer should work for different tree shapes.

The exercise combines recursive data structures with recursive graphics. It also illustrates that a visual representation is an interpretation of an underlying model: the node relationships are stored in the tree, while positions and lines are derived when the tree is rendered.

## Main Lesson

The three programs use different inputs, but they follow a common pattern: collect user or program data, convert it into a structured model, calculate geometry, and render the result. Keeping these responsibilities separate makes the applications easier to validate and extend.
