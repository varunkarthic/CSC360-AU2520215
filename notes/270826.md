## The `.m2` Directory in Maven

Maven stores downloaded dependencies and project metadata in the local repository. On most systems, this is located in the user home directory under `.m2/repository`. This folder is commonly called the **M2 repository** or simply the **local Maven repository**.

When a project references a library, Maven checks the local repository first. If the dependency is already present, it is reused without downloading it again. If the dependency is missing, Maven fetches it from a remote repository such as Maven Central and stores a local copy so future builds are faster.

This local repository is an important part of the build process because it separates the developer environment from the project file itself. The project configuration tells Maven what it needs, and Maven manages the actual installation and retrieval of those artifacts.

## Dependencies in Java and Maven Lifecycle

A dependency is an external library or module required by the application to compile and run correctly. In Java projects, dependency management is usually done through Maven by declaring the dependency inside `pom.xml`.

When Maven cannot find a required package locally, it searches the configured remote repositories and downloads the matching artifact. Maven may also use a linked or custom repository if one is configured in the project.

The Maven lifecycle includes phases such as `compile`, `test`, `package`, and `install`. The **install** phase copies the built project artifact into the local Maven repository so it can be used by other local projects. This makes the project available for local dependency resolution without being published to a remote repository.

## `.jar` Files and `.class` Files

Java source code is compiled into `.class` files, which contain bytecode that can be executed by the Java Virtual Machine (JVM). A `.class` file usually contains one compiled Java class.

A **JAR** file is a Java archive that packages compiled classes, resources, and metadata into one file. It is similar to a zip file but has a Java-specific structure. In the class, we expanded a `.jar` file and examined its contents to understand what it contains.

This distinction is important:

- `.class` files are the compiled output of a single class.
- `.jar` files bundle multiple classes and resources together for distribution or reuse.

The JAR file is not the same as the source code; it is a packaged build artifact produced from compiled code.

## Java Packages

A Java package is a namespace used to group related classes and interfaces. Packages help avoid naming conflicts and organise code logically. For example, classes might be grouped under a package such as `com.example.project`.

A JAR is created locally as an artifact of the project. It is not automatically installed globally. If the package or library is not present in the local environment, Maven can fetch it from a remote repository or install it into the local repository as needed.

The package structure corresponds to the folder hierarchy in the source code, and it is often reflected in the compiled JAR layout. This makes Java projects easier to manage when they become larger and depend on many libraries.

## Dependencies vs JAR Storage

A common misunderstanding is that a `.jar` file contains all of its dependencies. In reality, the JAR does not generally include its required external libraries. The dependency information is stored in the project's `pom.xml` file, and Maven resolves those dependencies at build time.

This means that the project configuration is the source of truth for the dependency graph. The `.jar` file contains the code written by the project, while the `pom.xml` file tells the build tool which external libraries are required and where to find them.

## Release Management and CI/CD

**Release management** is the process of preparing, testing, and distributing software versions. In modern development, this is often handled with a **CI server** or continuous integration server, which automates checking code changes.

A CI server monitors the repository and triggers automation whenever code is pushed or merged. The pipeline typically performs tasks such as:

- fetching the source code,
- installing dependencies,
- compiling the project,
- running tests,
- reporting failures.

**Continuous Integration (CI)** focuses on automatically building and testing code changes as they are integrated into a shared repository. **Continuous Delivery (CD)** goes a step further by automating the release process so that validated builds can be prepared for deployment to staging or production environments.

The overall idea is to keep software moving through automated verification and release stages with less manual work and fewer human errors.

## Character Sets and UTF-8

Text in Java is represented as sequences of characters, and these characters are encoded using a character set. A common encoding is **UTF-8**, while **UTF-16** is another widely used encoding.

UTF-8 is often preferred because it is space-efficient for many common characters and supports international text well. ASCII characters, for example, use only one byte in UTF-8, whereas UTF-16 uses at least two bytes for most characters. This makes UTF-8 more compact in many real-world cases.

The advantage of UTF-8 is therefore a balance between compatibility and efficiency. It is widely used for web content, programming files, and Java text processing because it stores common text efficiently while remaining capable of representing a wide range of characters.

## Source Version and Runtime Version

In Java, there is a distinction between the **source version** and the **runtime version**. The source version determines what language features are allowed in the code. The runtime version determines which Java version the program is intended to run on.

In Maven, the `compiler.release` setting is often used to define the target Java release. This tells the compiler to generate bytecode compatible with a specified version, such as Java 17. The source and target settings are usually close, because the project is written with that version in mind and the compiled output should match the environment it runs on.

For example, setting the release to 17 means the source code is compiled using Java 17 language rules and the produced bytecode is targeted to the Java 17 runtime.

## JUnit and Testing Levels

**JUnit** is the Java testing framework used for unit tests. It supports automated testing of individual methods and classes. There are several testing layers in software development:

- **Unit Testing** checks individual components or methods.
- **Integration Testing** checks whether different parts of the system work together.
- **Acceptance Testing** checks whether the software meets the business or user requirements.

These layers help verify the project at different levels of complexity. Unit tests are usually fast and focused, while integration and acceptance tests validate broader system behavior.

## Dependencies in `pom.xml`

Dependencies in Maven are declared in the `pom.xml` file. Each dependency usually contains: 

- `groupId`: the organisation or namespace,
- `artifactId`: the project or library name,
- `version`: the version being used.

This file acts as the project manifest for build configuration. It tells Maven which libraries to fetch, which Java version to use, and how the project should be compiled and packaged. Without the `pom.xml`, Maven would not know how to resolve the project dependencies or build it consistently.

## JavaFX

JavaFX is a Java framework used to build rich desktop applications with a graphical user interface. It provides a modern UI toolkit with features such as controls, layouts, and media support.

JavaFX includes components such as:

- **Controls**: buttons, text fields, labels, tables, and other interface widgets,
- **FXML**: a declarative markup language for designing UI layouts,
- **Web**: support for embedding web content,
- **Media**: support for audio and video playback.

JavaFX is useful for building more advanced desktop interfaces than the basic AWT/Swing approach. It separates the UI design from logic and helps structure applications in a more modern way.
