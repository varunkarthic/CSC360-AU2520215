## Event Handlers and Event Sources

An event handler is code that responds when an event occurs in a user interface. Examples include a button click, a mouse movement, a key press, or a change to a control's value. The event source is the control that produces the event, while the handler contains the action that should be performed. In JavaFX, a handler can be attached using methods such as `setOnAction`, `setOnMouseClicked`, or `setOnKeyPressed`.

The event object contains information about what happened and, in some cases, which control generated the event. Keeping the event source and the response separate makes the program easier to understand and allows the same handler logic to be reused by multiple controls. Event-driven programs wait for user or system activity rather than executing every action in a fixed sequence.

## Collections in Java

Java collections provide standard structures for storing and processing groups of objects. A `List` preserves order and allows indexed access, so it is useful when the position of each item matters. A `Queue` represents items waiting to be processed, usually in first-in-first-out order. A `Set` stores unique values and is useful when duplicates should be removed or membership needs to be checked. A `Map` stores key-value pairs and is useful for looking up one value using another value as a key.

The collection should be selected according to the operation the program performs most often. For example, a map can quickly find a job by its identifier, a queue can hold pending jobs, and a list can preserve the order in which results are displayed. Generics specify the element types and help the compiler detect invalid values before the program runs.

## Grid Layout and Border Layout

`GridPane` arranges controls in rows and columns. It is useful for forms, tables of controls, and interfaces where each item needs a predictable row and column position. Column and row constraints can control how available space is distributed, while gaps and padding improve readability.

`BorderPane` divides a window into five regions: top, bottom, left, right, and center. It is useful for an application shell with a toolbar or menu at the top, navigation on the side, status information at the bottom, and the main content in the center. A layout can combine both panes, such as placing a `GridPane` form inside the center of a `BorderPane`.

## Composite Progress Bar for Multiple Jobs

One exercise was to create a JavaFX program with a composite progress bar that tracks several jobs and supports cancellation. Each job can be represented by a JavaFX `Task`, which reports progress as it runs. The user interface can show one row per job with its name, individual progress bar, status, and cancel button. A composite progress indicator can calculate an overall value from the progress of all active jobs, such as the average progress or a weighted total.

Cancellation should be cooperative. Pressing a cancel button requests cancellation on the corresponding task, and the task checks that request while it performs its work. The user interface must be updated on the JavaFX application thread, while the long-running job itself runs on a background thread. This keeps the window responsive and allows the remaining jobs to continue when one job is cancelled.

## Combining Swing and JavaFX Components

Another exercise was to write a JavaFX user interface that uses both Swing and JavaFX components. JavaFX can host Swing content through `SwingNode`, while Swing can host JavaFX content through `JFXPanel`. The two toolkits use different UI threads, so updates must be made on the correct thread: JavaFX changes belong on the JavaFX Application Thread and Swing changes belong on the Event Dispatch Thread.

Mixing the toolkits can be useful when an existing Swing component needs to be reused in a newer JavaFX application. It also requires care with focus, sizing, event handling, and thread boundaries. The interface should keep the bridge between the toolkits small so that the ownership of each component remains clear.

## Master-Detail Layout

The master-detail exercise used one area to display a collection of items and another area to display details for the selected item. A `ListView`, `TableView`, or similar control can act as the master, while labels, text fields, images, or other controls show the selected detail. A selection listener or a property binding keeps the detail view synchronized with the current selection.

A master-detail design is useful because it shows many items without displaying every property at once. The layout can be created with a `SplitPane`, `BorderPane`, or a combination of containers. The program should also handle an empty selection by clearing the detail fields or displaying an appropriate default state.

## Styling a Single Geometric Object

The geometric-object exercise created a JavaFX interface for changing the appearance of one shape. A `Shape` such as a rectangle, circle, or polygon can be placed in a drawing area, while controls allow the user to change properties such as fill color, stroke color, stroke width, size, rotation, or opacity.

The controls should be connected to the shape through event handlers or property bindings. Separating the shape from the editing controls makes it possible to add more objects later. It also demonstrates that JavaFX scene-graph nodes are both visual objects and observable properties that can be changed while the application is running.

## Browser Support and DOM Interaction

The browser-support exercise used JavaFX `WebView` and `WebEngine` to display a web page inside a JavaFX application. A JavaFX button can call JavaScript through the web engine, for example by using `executeScript` to change the text, style, or other property of a DOM element. The page must be loaded before the script is executed, so the code should respond to the web engine's load worker state or otherwise wait for the page to finish loading.

This creates a bridge between the JavaFX scene graph and the browser DOM. JavaFX controls handle the desktop application interaction, while HTML, CSS, and JavaScript handle the embedded page. The boundary between the two environments should be explicit, and values passed into JavaScript should be validated and safely encoded.

## Main Lesson

The topics connected application structure, data representation, and user interaction. Events determine when work happens, collections determine how information is stored, and layout panes determine how controls are arranged. The exercises then applied those ideas to background jobs, mixed UI toolkits, selection-based views, editable graphics, and browser content.
