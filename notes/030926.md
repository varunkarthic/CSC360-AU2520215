# Java Drawing, Collections, and JavaFX FXML
*Thursday, 3 September 2026*

## Topics Discussed

- Printing an ASCII tree in Java
- Drawing arrows between two lists with common elements
- Building a custom JavaFX splash screen with FXML

## ASCII Tree

The first exercise was to write a Java program that prints a tree using text characters. A simple solution prints spaces before each level and uses characters such as `/`, `\\`, and `|` to represent branches and the trunk. The number of spaces and branch characters must be calculated from the current depth so that the tree remains centred as its height changes.

This problem is a text-based version of the binary-tree drawing problem. Instead of pixels and canvas coordinates, the program works with rows and columns. The output can be generated recursively: print the current level, then generate the next level with the correct horizontal spacing. Another approach is to represent each row as a character array, place nodes and branches at calculated positions, and print the completed row.

The exercise demonstrates that layout problems occur even when the output is plain text. The program must consider width, alignment, tree height, and the relationship between parent and child positions.

## Arrows Between Two Lists with Common Elements

The second exercise was to draw arrows between two lists when they contain common elements. One list is placed on the left side of the drawing area and the other on the right. For every value that occurs in both lists, the program finds the matching item and draws a directed arrow from the position in the first list to the position in the second list.

The data-processing step should happen before rendering. The program can build a lookup map from values in the second list to their positions, then iterate through the first list and identify matches efficiently. If duplicate values are allowed, the data model must specify whether one-to-one, one-to-many, or all matching connections should be drawn. The visual layer then uses the calculated row positions to draw the list labels and arrow lines.

The arrow geometry is similar to the previous class: the line should begin and end near the boundaries of the list items, and its arrowhead should point toward the matching item. If several arrows cross, the layout may need horizontal offsets or curved paths to keep the relationships readable. This is an example of visualising a relationship between two collections rather than drawing unrelated shapes.

## Custom JavaFX Splash Screen with FXML

The third exercise was to create a custom splash screen using FXML. FXML is an XML-based declarative format for describing a JavaFX user interface. The layout can define a root container, images, labels, progress indicators, and styling without placing all UI construction code inside the Java class.

The JavaFX application starts by loading the FXML file with `FXMLLoader`. The resulting scene is placed in a stage that can be styled as a custom window. A splash screen may use an undecorated stage so that the application controls the visible border, background, and branding. After a short loading operation, the splash stage can be hidden and the main application stage can be displayed.

The controller manages behavior such as updating a progress indicator, responding to a timer or background task, and switching to the main view. Long-running work should not block the JavaFX application thread. If loading takes time, the work should be performed using a background `Task`, while UI updates are made on the JavaFX thread.

This exercise demonstrates separation of concerns. FXML describes the structure and appearance, the controller handles interaction, and the application class manages stages and startup. CSS can be added for styling without changing the Java code.

## Main Lesson

These exercises showed three forms of visualisation: text output arranged in rows and columns, graphical relationships between two data collections, and a structured JavaFX interface described with FXML. In all three cases, the quality of the output depends on building a clear representation of the data before deciding how to display it.
