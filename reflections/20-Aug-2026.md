## Reflection

Studying the square program helped me see that a graphics application depends on both Java structure and geometric reasoning. The program became easier to understand once I connected `App` as a subclass of `JPanel` and `new App()` as the creation of an instance.

The `@Override` annotation showed me how a subclass can provide a more specific implementation of a method inherited from its parent. In this example, `App` overrides `paintComponent` so that it can add its own drawing instructions.

Learning about `super` clarified why `super.paintComponent(g)` is called before drawing. It allows the parent `JPanel` behavior to run first, after which the subclass can safely add the blue square.

The discussion of lines, rectangles, and triangles showed me that larger graphical objects can be constructed from simple primitives and connected vertices. The boundary method also made the triangle feel more algorithmic because its outline can be generated from three edges rather than treated as a single unexplained shape.

Overall, analysing an existing square program was useful because every line of code could be connected to a Java concept or a geometric operation. I now have a clearer foundation for extending the program to draw other shapes.
