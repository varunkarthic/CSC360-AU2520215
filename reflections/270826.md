## Topics Discussed

- The `.m2` directory and the local Maven repository
- Dependencies in Java and installation through Maven
- The difference between `.class` files and `.jar` files
- Java packages and dependency resolution
- Release management and CI/CD
- Character encoding, especially UTF-8 and UTF-16
- Source version versus runtime version
- JUnit testing levels
- JavaFX components and capabilities

## Reflection

This class helped me understand that Maven is not only about compiling code; it is also about managing dependencies, package resolution, and local project artifacts. The `.m2` directory became clearer when I learned that it acts as the local repository where Maven stores downloaded libraries and installed project artifacts. This means builds can reuse dependencies instead of retrieving them repeatedly from the internet.

The discussion of `.class` and `.jar` files showed the difference between compiled bytecode and packaged application artifacts. A `.class` file is tied to one class, while a JAR groups multiple files into a single archive. Learning that the JAR does not usually contain dependencies was especially important because it reminded me that `pom.xml` is the source of truth for dependency information.

The release-management topic made me see how software is moved through automated stages in real development. CI focuses on regularly building and testing code as it is merged, while CD helps deliver validated builds to later environments. This is a practical reminder that programming is not only writing code but also ensuring that code can be safely built, tested, and published.

The discussion on character encoding and Java versions also connected to the broader software engineering context. UTF-8 is often preferred because it is efficient, while setting the correct source and runtime version ensures that the code compiles with the right language features and runs on the correct Java version. The JUnit section reinforced the importance of testing at several levels, from small unit validations to larger integration and acceptance checks.

Finally, JavaFX gave me a sense of how desktop applications can be designed with a richer set of controls and structure. It showed me that Java is not limited to the console or basic Swing libraries; it can also support more modern interface patterns with controls, FXML, media, and web integration.

Overall, this lesson brought together build tools, Java packaging, testing, release workflows, and UI frameworks. It gave me a stronger understanding of how Java projects are organised and how real-world software is maintained beyond just writing a single class or method.
